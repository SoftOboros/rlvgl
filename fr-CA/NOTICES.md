- `chipdb/rlvgl-chips-stm/db/` — Enregistrements JSON **intermédiaires/dérivés** ou similaires produits à partir de l'amont.
- `chipdb/rlvgl-chips-stm/src/` — Code de crate qui **accède** aux données embarquées dérivées de l'amont.

**Comment ce matériel est utilisé ici :**
- Les fichiers XML/CSV en amont sont normalisés en JSON canonique (AF/pin/signaux).
- Ces enregistrements canoniques sont empaquetés dans des artefacts compressés pour être utilisés au moment de la construction/exécution.
- Le code BSP est généré (formats HAL et PAC) qui **exprime** les sélections pinmux/AF ; ces fichiers incluent des en-têtes d'attribution.

**Attribution dans les fichiers générés :**
Tous les fichiers générés qui incluent ou expriment du contenu dérivé de l'amont comportent un en-tête SPDX similaire à :

## Comment ajouter un nouvel avis de fournisseur (pour les ajouts futurs)

Lors de l'ajout de données spécifiques à un fournisseur :

1. Placez le texte de la licence du fournisseur dans l'arborescence pertinente (par ex. `vendor_data/<vendor>/LICENSE.*`).
2. Ajoutez une section comme celle de STM ci-dessus avec :
   - Nom, licence et copyright de l'amont
   - Provenance (URL/commit source, version)
   - Chemins locaux couverts
   - Comment il est utilisé/dérivé
3. Assurez-vous que les fichiers générés qui incluent du contenu dérivé du fournisseur comportent un en-tête SPDX approprié :
   ```
   // SPDX-FileCopyrightText: <année> <Fournisseur ou Titulaire du droit d'auteur>
   // SPDX-FileCopyrightText: 2025 Softoboros Technology, Inc.
   // SPDX-License-Identifier: <Licence-Fournisseur> AND MIT
   ```
4. Incluez le texte de la licence du fournisseur dans toute crate publiée qui **intègre** les données dérivées (par ex. sous `LICENSES/` dans le paquet de la crate).
