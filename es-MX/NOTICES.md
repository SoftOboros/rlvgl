**Proyecto upstream:** STMicroelectronics — “STM32_open_pin_data”
**Licencia:** BSD-3-Clause (ver `chips/stm/STM32_open_pin_data/LICENSE`)
**Copyright:** © 2020 STMicroelectronics

**Procedencia (rellenar cuando esté fijado):**
- Commit upstream: `3d64b1076ac7f0bf0f74acf89b9578b530f37ed7`
- Obtenido vía: Submódulo de Git en `chips/stm/STM32_open_pin_data` (solo lectura)
- Referencia: CubeMX DBVersion `6.15.0`

**Rutas locales cubiertas por este aviso:**
- `chips/stm/STM32_open_pin_data/` — Contenido **textual upstream**.
- `chips/stm/mcu/` — Datos de pines/AF de MCU canónicos **derivados** generados a partir del upstream.
- `chips/stm/boards/` — Descripciones de nivel de placa **derivadas** construidas a partir de los datos de MCU upstream y la documentación pública de las placas.
- [`chips/stm/bsps/`](chips/stm/bsps/README.md) — Fuentes BSP de Rust **generadas** que incorporan/expresan asignaciones derivadas del upstream.
- [`chipdb/rlvgl-chips-stm/assets/`](chipdb/rlvgl-chips-stm/assets/README.md) — Artefactos de base de datos comprimidos **incrustados** (por ejemplo, `*.tar.zst`) construidos a partir de los datos upstream.
- `chipdb/rlvgl-chips-stm/db/` — Registros JSON o similares **intermedios/derivados** producidos a partir del upstream.
- `chipdb/rlvgl-chips-stm/src/` — Código de crate que **accede** a los datos incrustados derivados del upstream.

**Cómo se utiliza este material aquí:**
- El XML/CSV upstream se normaliza a JSON canónico (AF/pines/señales).
- Esos registros canónicos se empaquetan en artefactos comprimidos para su uso en tiempo de compilación/ejecución.
- Se genera código BSP (formas HAL y PAC) que **expresa** las selecciones de pinmux/AF; estos archivos incluyen encabezados de atribución.

**Atribución en archivos generados:**
Todos los archivos generados que incluyen o expresan contenido derivado del upstream llevan un encabezado SPDX similar a:

```text
/* Auto-generated by rlvgl-creator
 * SPDX-FileCopyrightText: 2020 STMicroelectronics
 * SPDX-FileCopyrightText: 2025 Softoboros Technology, Inc.
 * SPDX-License-Identifier: BSD-3-Clause AND MIT
 * Provenance: STM32_open_pin_data ( commit 3d64b1076ac7f0bf0f74acf89b9578b530f37ed7 ), build <build-hash>.
 */
```

> Notas:
> - "AND MIT" aparece cuando el archivo generado también incluye elementos de código de Softoboros (ayudas/shims) con licencia MIT en este repositorio.
> - La redistribución de cualquier paquete o artefacto que contenga estos archivos debe conservar el aviso **BSD-3-Clause** de ST y el aviso **MIT** de Softoboros.

## Cómo añadir un nuevo aviso de proveedor (para futuras adiciones)

Al añadir datos específicos del proveedor:

1. Coloque el texto de la licencia del proveedor en el subárbol relevante (por ejemplo, `vendor_data/<vendor>/LICENSE.*`).
2. Añada una sección como la de STM anterior con:
   - Nombre del upstream, licencia y copyright
   - Procedencia (URL/commit de origen, versión)
   - Rutas locales cubiertas
   - Cómo se utiliza/deriva
3. Asegúrese de que los archivos generados que incluyen contenido derivado del proveedor lleven un encabezado SPDX apropiado:
   ```
   // SPDX-FileCopyrightText: <año> <Proveedor o Titular del Copyright>
   // SPDX-FileCopyrightText: 2025 Softoboros Technology, Inc.
   // SPDX-License-Identifier: <Licencia-Proveedor> AND MIT
   ```
4. Incluya el texto de la licencia del proveedor en cualquier crate publicado que **incruste** los datos derivados (por ejemplo, en `LICENSES/` en el paquete del crate).
