## Original manifests and complete generated-member accounting

Wave2 removed dependency path fields and excluded generated members from its
inventory comparison. This experiment **preserves each original package
manifest byte** and compares complete Cargo inventories, including
`Cargo.toml`, `Cargo.toml.orig`, `Cargo.lock` and `.cargo_vcs_info.json`.
Cargo performs normalization and generates the archives; no final manifest or
archive member is edited afterward.

The external Git input is a local shared-object, no-checkout clone at the
candidate HEAD. Only Cargo-listed package payloads and exact package manifests
are copied into package-shaped paths. API/core relative sibling aliases point
to newly extracted predecessor archives. No live sibling sources are copied
as a packaging or consumer fallback. Missing widgets/decomp/playit paths are
not fabricated; Cargo's fresh detached packaging normalizes those paths without
traversing them in the successful three-package run.

Commands use `CARGO_NET_OFFLINE=true`, an external `CARGO_TARGET_DIR`,
`cargo package --list --allow-dirty` on source packages and
`cargo --config <progressive.toml> package --allow-dirty --no-verify` on
external inputs. The progressive table retains extracted API and core. These
are packaging diagnostics; `--no-verify` is not a consumer build or test.

categories, license, exclude, edition and rust-version from vendor workspace
package settings. All eight fields and the entire inherited lint table match
the actual retained Cargo-normalized manifest. Source `cargo metadata --no-deps`
also confirms:

The external ancestor copies workspace package/dependency/lint descriptors
verbatim but narrows members/default-members to the bridge. This projection
removes unrelated workspace resolution and is explicitly not whole-workspace
equivalence. Its inherited ratatui-core path initially fails because absent.
The coordinator admitted one bounded public archive download within the accepted

No package toolchain/component installation or live source fallback occurred.

A first offline projected package succeeds with a fresh ancestor lock, but its
packaged lock differs from the retained reference: 14 added and 13 removed

This proves descriptor and packaged-content equivalence for this bridge
fixture. It does not prove pinned vendor ratatui-core implementation equivalence
to the public archive, full vendor-workspace resolution, all consumers or the
governed stager's lock restoration. The chosen registry archive supplies only
the explicitly recorded external inherited dependency route.

## Negative controls and exact core source-lock stop

1. Removing the extracted core patch makes unchanged platform packaging fail
   with exit 101 at `rlvgl-core ^0.2.7`, even though its original relative path
   aliases the extracted core. Restoring the patch succeeds. No dependency
   minimum was lowered and no live fallback appeared.
2. Removing Git context lets API packaging complete, but creates eight members
   rather than nine: `.cargo_vcs_info.json` is missing. Complete inventory
   comparison detects this provenance failure rather than dropping that member.
3. One offline core trial, admitted by the coordinator within the accepted
   exploratory scope, starts with an exact copy of the root source
   Cargo.lock placed beside the unchanged detached core manifest. It fails
   with exit 101 while loading path-only `rlvgl-widgets` from the absent
   `git-input/widgets/Cargo.toml`. Thus the fresh-lock success above does **not**
   settle source-lock/whole-graph equivalence. The copied lock stays byte-identical
   to source. No widgets source or invented manifest is supplied to bypass it.

The exact core error is retained in `core-source-lock-package.log`. The source
root lock hash remains
`4471e27af890241eee1f0479782ba983515fadd19d7afc29e32a7989b71893a7`;
the source vendor lock hash remains
`dd746d8977165b004a3af7097a298af9b8172742ed88db15a121100da46a4f6a`.
Both match the assembled root candidate after these experiments. No original
lock was replaced, deleted or normalized.

## Owner packet and retained stops

This materially narrows the wave2 gaps: original package manifests, every
generated member, payload content, Git record identity and bridge inheritance
can be preserved in an external Cargo-owned experiment. It also exposes a
specific remaining boundary: retaining the whole source lock can force
path-only dev graph traversal before packaging. The owner must dispose of the
exact detached-input/ancestor/lock mechanism and its equivalence requirements
before governed implementation. A successful fresh-lock subset cannot answer
that policy question or close the failing original-lock case.

Remaining gates include clean-source refusal, metadata and published-content
drift negative controls, success/failure lock restoration, normal asset
preparation, all 31 publishable packages, fresh library/creator/user-sim consumer
locks and metadata, Linux proof, exact publication and chosen parent pin. The
13-package changed publisher selection remains separate from full-set Gate P.
No governing script, runtime, manifest, index, phase acceptance, tag, branch,
registry upload, hardware or cloud service was changed.
