both provisioning variables were removed from the child process environment:

```sh

# examples/beetle-esp32c6: riscv32imac-unknown-none-elf
env -u RLVGL_WIFI_SSID -u RLVGL_WIFI_PASSWORD \
  CARGO_TARGET_DIR=/private/tmp/rlvgl-v027-integration-ocwvej23/rlvgl/target \
  CARGO_NET_OFFLINE=true cargo build --release \
  --bin rlvgl-beetle-esp32c3-network-time --features esp_hal_network_time
```

From `examples/beetle-esp32c6`, the exact second build command was:

```sh
env -u RLVGL_WIFI_SSID -u RLVGL_WIFI_PASSWORD \
  CARGO_TARGET_DIR=/private/tmp/rlvgl-v027-integration-ocwvej23/rlvgl/target \
```

 No `cargo run` or flash/monitor runner was
invoked. Both were complete release links, not compile-only checks. No SDK or
new board toolchain was installed.

`espflash save-image --chip esp32c3|esp32c6 --flash-size 4mb --merge ELF OUTPUT`

The [September 30 C6 bench receipt](../../examples/beetle-esp32c6/README.md#saved-network-bench-regression-2026-09-30)
remains historical evidence. It records two application-only flashes loading
`Stored`, generation 1, then DHCP plus stratum-3 SNTP with 41/42 ms round trips.
Those observations were not repeated, refreshed or attributed to the newly
built candidate. The historical tested ELF hash remains
`968dec52cf89865fdd167023ddbafb9f34660346916fe81c46a06558fa4bf2ed`.

Saved credentials remain distinct from ephemeral discovered open-network
candidates. Host record tests and credential-free linking do not prove actual
NVS persistence across these new images. DHCP alone is not usable-network proof;
the shared runner still requires a valid SNTP response.

OLED visual confirmation, physical open-network fallback/captive-portal
behavior, exhaustive warm-reset recovery, and new-image physical C3/C6 network
regression remain open. No linked image or software test closes those items.
