# v0.2.7 continuation source and gate review

October 5, 2026 historical proposal. The [October 6 owner decision and local
implementation](v0.2.7-continuation-decision.md) supersede its pending disposition.
At the time of this receipt the correction was proposed, not adopted. Owning tracking:
[CRATES-CI ERRATA-002 / EOQ-002-ERRATA-002](../crates-ci/ERRATA.md).

## Observed behavior

The current `.github/workflows/publish-continue.yml` checks out the workflow
revision, resolves the latest and previous tags, preserves the publisher helper,
then executes that helper against the same workflow checkout. It records the
latest tag SHA but never checks out that source. Its sole publish job has no
Gate P dependency. Thus later workflow revisions can supply unqualified crate
sources to a continuation of a tagged release. This is a static source finding
and a faithful local resolver reproduction, not evidence of an actual bad upload.

The local three-commit/two-tag fixture runs the exact current tag-resolution
bash block. It resolves the latest tag while HEAD remains a different later
commit. The workflow's SHA-256 is
`f1318e991bdf20e29fb49a6187906e7f3aa3ec450c9ecc6e3d674a1667f9af1e`.

CRATES-CI-00 §5.4 names `publish.yml`; §5.5 admits both publisher workflows.
INV-C1 and INV-C6 require release-ref qualification. The current continuation
comment explicitly permits the workflow revision. The proposed correction
therefore needs an owning clarification/amendment before governed implementation.

## Concrete review draft

An external YAML and unified patch preserve selection cadence, ordered publisher,
release Environment and OIDC publishing permissions. The two nonpublishing jobs
explicitly grant only `contents: read`. A resolver freezes the latest tagged
commit; annotated tags are peeled to commits. Gate P and publication both check
out that exact SHA. All three existing packaged consumers are retained. Publication
needs successful Gate P before its authentication step. The current workflow's
helper can still be preserved for maintenance, but its revision is recorded
separately from the frozen crate sources. A guard checks exact HEAD and clean
source before authentication. A later moving tag cannot alter the captured SHA.

Local controls run the proposed source guard against the synthetic later HEAD
(exit 1), clean tagged commit (exit 0) and dirty tagged commit (exit 1). An
annotated-tag fixture resolves to its underlying commit. YAML parsing and
dependency-graph checks pass.
These controls do not execute GitHub, packaging or consumers. Gate P remains
blocked by ERRATA-001, so the draft cannot authorize a release.

Draft and evidence are preserved at
`/private/tmp/rlvgl-v027-integration-ocwvej23/wave3/continuation-audit/`:
`publish-continue-proposed.yml`, `publish-continue-proposed.patch`, `receipt.json`,
`proposed-graph-audit.json` and `source-guard-controls.json`.
The governed workflow is byte-identical to the baseline. Nothing was uploaded,
scheduled or authenticated.

## Required owning disposition

Decide whether continuation must resume the latest tagged candidate with Gate P
on that same commit, while optionally using a separately identified newer helper.
If adopted, amend §5/§15, implement and test the provider graph, source controls
and complete packaged consumers after the staging mechanism is settled. A helper
repair that also needs crate-source changes requires a newly qualified candidate;
the draft does not authorize mixing them into the prior tag.
