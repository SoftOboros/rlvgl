# v0.2.7 Gate P correction proposal

Status: proposal for release review; not a ratified mechanism change.

## Observed failure

The selected-package staging run packages ESP chip data, the four device
drivers, Kria, API, core, and the Ratatui bridge. It then fails on platform:

```text
failed to select a version for rlvgl-core = ^0.2.6
candidate versions found: 0.2.5, 0.2.4, ...
```

This failure was observed before the owner-selected core bump to `0.2.7`.
The current candidate requires `^0.2.7`; the same staging defect remains.

The current mechanism defers extracted core and bridge patches after packaging
the bridge. A later sanitized platform manifest cannot resolve the unpublished
core version without that patch. Retaining the extracted core patch instead
produces a lockfile collision between live and extracted `rlvgl-api 0.2.1`;
both identities occur in the root workspace graph.

The version selection is intentional: platform must declare the native core
version used by this candidate. Lowering its requirement to disguise the
packaging failure would weaken the dependency claim.

### Current core 0.2.7 diagnostic

The October 5 bounded online retry packages API 0.2.1, core 0.2.7 and bridge
0.1.1, then reproduces the deferral failure at platform:

```text
failed to select a version for the requirement rlvgl-core = ^0.2.7
candidate versions found which didn't match: 0.2.5, 0.2.4, 0.2.2, ...
```

The initial offline retry stopped earlier on the nested workspace's
rand/chacha20 resolver path. The online packaging retry cleared that earlier
failure; it does not establish standalone nested-workspace test resolution.
Both logs are retained in the local `wave1/release-logs/` evidence directory.
No staging-script behavior was changed.

## Proposed correction

Package each selected crate in an isolated packaging workspace containing the
exact package source inventory, with dependency paths lowered to their declared
registry versions. Continue packaging in dependency order and feed each command
only the progressively extracted candidate patch table. The isolated workspace
has no live sibling members, so one package/version has one source identity.

Keep the final consumer patch table rooted exclusively in extracted archives.
Preserve clean-source refusal, packaged metadata checks, published-content drift
checks, package-order checks, and the library/creator/user-simulator consumers.
Restore any temporary lockfiles and leave the original working checkout intact.

Before adopting the correction, prove that the source inventory and normalized
manifest match Cargo's normal package inventory; prove refusal on a missing
staged dependency and acceptance when its predecessor is staged; then run all
Gate P consumers with no source-workspace route available.

## Authority

[CRATES-CI-00 §6](../crates-ci/CRATES-CI-00-CONCEPTS.md) currently requires the
partial extracted patch table before each package command and explicitly
specifies the core/bridge deferral. Its mechanism is marked Specification
Required. Adopting the isolation correction therefore needs an amendment to
that chapter before it becomes the release's default behavior. This proposal
does not waive Gate P or count local-source bootstrap packaging as Gate P.

[CRATES-CI-01b](../crates-ci/CRATES-CI-01B-STAGING-ISOLATION.md) now carries the
draft exact boundary and acceptance controls, with the open mechanism decision
recorded as [ERRATA-001](../crates-ci/ERRATA.md). It remains unratified.
