# KI2C software preparation for v0.2.7

Prepared 2026-10-05. This is a design packet, not a new KI2C phase, executable
command, adopted schema, physical result, or amendment. [KI2C-00](../concepts/KI2C-00-CONCEPTS.md)
remains the normative authority. [KI2C-06 §14](../concepts/KI2C-06-KRIA-INTEGRATION.md)
explicitly unblocks software-side command/example design and a versioned
conformance-log schema; [KI2C-07](../concepts/KI2C-07-HARDWARE-CONFORMANCE.md)
remains hardware-blocked.

## Proposed command/example boundary

A later bounded application example can compose the accepted six crates and
caller-owned `PhysicalBusMap`, `KriaI2cBuses`, and `ProbeDiagnostic` types.
It adds no drivers, register operations, GPIO/clock ownership or controller
discovery. Its input is an explicitly supplied board/image/bus/prerequisite
manifest; output preserves per-operation results and evidence locators.

The proposed command has two explicit modes: a default software preflight that
validates supplied metadata without opening controllers, and a separately
authorized read-only smoke mode. This interface is not implemented. Preflight
reports missing prerequisites without inferring adapter numbers or opening
`/dev/i2c-*`; a filename or address ACK is not proof of board topology.

| Proposed input | Purpose |
|---|---|
| Input manifest path | Supplies all KI2C-07 §5 source, board, image, mapping and electrical facts. |
| Output path/run identifier | Names a new record; no overwrite of earlier evidence. |
| Explicit read-only operation selection | Names only admitted typed probes; no broad address scan or configuration writes. |
| Operator authorization locator | Identifies permission for the exact controllers and read-only operations. Its absence keeps controller access blocked. |

The future implementation follows the Qwen executor/Llama judge discipline
in KI2C-00 §9 and the parent ClosedClaw authority. A one-candidate-path PUT
keeps fixed tests and scaffolding outside the candidate write surface. This
design and the existing deterministic tests do not replace that model-loop or
human-review requirement. No implementation turn or judge verdict is claimed.

## Probe plan and unresolved temperature step

As defined in KI2C-00 §2 and KI2C-07 §6, the admitted map is:

| Device | Logical bus | Seven-bit address | Proposed read-only action |
|---|---|---:|---|
| STTS22H | `PsI2c1` | `0x38` | Typed identity probe after the existing boot-delay and `TEMP_ADDR` obligations; temperature step stops at the discrepancy below. |
| VEML3235SL | `PlFrontPanelI2c` | `0x10` | Typed identity probe; raw ALS/white capture only when a known active configuration and settling provenance are supplied. Otherwise retain the skip reason. |
| PTN3460 | `PlFrontPanelI2c` | `0x20` | Typed configuration-magic health read; preserve raw magic and `configuration_valid`. This is not a silicon-identity claim. |
| PCM3168A | `PlFrontPanelI2c` | `0x44` | Typed reset-state health read only after real rail/reset/synchronous-clock and electrical evidence permits board-owned `HardwareReady`. This is not a silicon-identity claim. |

PS I2C0 remains mapped/opened only in the admitted smoke procedure; EEPROM U6
receives no transaction. The shared PL controller has one owned backend and
single-threaded lent handles, released before the bus bundle. No stronger
thread/interrupt/multicore sharing is inferred.

There is a concrete owner-decision gap for temperature capture:

- KI2C-07 §6 asks for a coherent temperature read without changing configuration.
- [KI2C-02 §7](../concepts/KI2C-02-STTS22H.md) requires successful configuration
  before that read, to force BDU and address auto-increment.
- The accepted [driver](../../devices/rlvgl-device-stts22h/src/lib.rs) starts
  with `config: None`; `read_temperature` returns `NotConfigured` before any
  bus transaction until `configure` succeeds. No public operation imports an
  observed external configuration into that local state.

A fresh read-only application cannot complete that temperature step through
the accepted API. The proposed preflight marks it prerequisite-blocked and
retains the discrepancy for owner disposition. It does not call `configure`,
invent a configuration-adoption API, relax coherent-read guarantees, or silently
change KI2C-07. Any resolution that changes a contract needs its owning phase
decision/amendment before implementation.

## Versioned capture-record design

The proposed record is a JSON representation of KI2C-07 §7, with a version
tag and explicit per-operation evidence/attempt/error fields. The following is
a shape proposal, not recorded observations or an executable JSON Schema:

```json
{
  "schema_version": "ki2c-conformance/v1 (proposed)",
  "run_id": "<unique run identifier>",
  "timestamp_utc": "<actual observation time>",
  "operator": "<operator identity>",
  "board_model": "<observed model>",
  "board_revision": "<observed revision>",
  "board_asset_id": "<observed asset or serial identifier>",
  "rlvgl_commit": "<exact source commit>",
  "application_commit": "<exact application commit>",
  "bitstream_sha256": "<deployed image digest>",
  "device_tree_sha256": "<deployed device-tree digest>",
  "runtime_version": "<actual OS/kernel or BSP>",
  "logical_bus_mapping": {
    "PsI2c0": "<caller-resolved physical controller>",
    "PsI2c1": "<caller-resolved physical controller>",
    "PlFrontPanelI2c": "<caller-resolved physical controller>"
  },
  "temp_addr_high_impedance": "<observed value plus evidence locator>",
  "pl_pullup_voltage_v": "<measured value plus instrument/capture locator>",
  "pcm_input_threshold_assessment": "<assessment and applicable source locator>",
  "pcm_rails_stable": "<observed value plus evidence locator>",
  "pcm_reset_released": "<observed value plus evidence locator>",
  "pcm_clocks_synchronous": "<measured SCKI/BCK/LRCK evidence locator>",
  "results": [
    {
      "logical_bus": "<admitted LogicalBus>",
      "physical_identifier": "<resolved controller>",
      "seven_bit_address": "<admitted address>",
      "operation": "<exact typed operation>",
      "attempted": false,
      "result": "prerequisite-blocked",
      "value": null,
      "leaf_error": null,
      "backend_error": null,
      "reason": "<specific missing prerequisite or decision>",
      "evidence_locators": []
    }
  ],
  "unattempted_operations": ["<operation and exact cause>"],
  "notes": "<bounded observations and unresolved obligations>"
}
```

The final field types and validation implementation remain a later reviewed
application artifact. A physical record requires actual values and locators;
these placeholders cannot qualify a board. Additional metadata can retain
source-tree/build-artifact hashes, tool versions, operator authorization,
instrument identities and teardown results without replacing the required
KI2C-07 fields.

Result values cite the existing KI2C-07 §3 vocabulary: `pass`, `bus-error`,
`semantic-failure`, `prerequisite-blocked`, `not-admitted`. The design adds no
new conformance result. NACK detail remains in the exact backend error; it is
not collapsed into identity mismatch. Preserve successful typed health payloads
as returned, including a false PTN configuration-valid flag; do not fabricate a
leaf error or identity verdict from it. Any application pass/fail expectation
for that value comes from its identified board test contract.

## Preconditions and stopping boundary

Before any controller access, the later operator supplies all KI2C-07 §5
facts, including physical mapping and permission. `TEMP_ADDR`/`PS_MIO36`
remains high-impedance; software does not assert GPIO ownership. The measured
PL peripheral-side pull-up voltage and PCM input-threshold assessment remain
visible even after a successful transaction. PCM readiness also includes
stable rails, released reset, synchronized clocks and the board-owned timing,
mute/settling responsibilities in KI2C-05. No token is synthesized from an
assumed healthy bus.

EEPROM U6 remains excluded pending exact part/capacity/address-width/page/write
timing evidence. KSZ9897S remains excluded pending board wiring, I2C-mode and
strap evidence. PTN EDID/flash/link changes, broader PCM control, configuration
writes, audio streaming and electrical remediation remain outside this design.

The deliverable stops at this software design and the separate
[verification receipt](v0.2.7-ki2c-evidence.md). Hardware conformance, the
temperature discrepancy, application/schema implementation and any affected
phase decision remain open. No controllers were opened and no board result is
claimed.
