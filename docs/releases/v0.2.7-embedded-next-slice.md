## KI2C owner amendment and admission packet

[KI2C-06 §14](../concepts/KI2C-06-KRIA-INTEGRATION.md) permits software
preparation. [KI2C-07 §4/§6](../concepts/KI2C-07-HARDWARE-CONFORMANCE.md)
requires read-only smoke probes and a coherent STTS22H temperature read without
changing configuration. [KI2C-02 §6/§7](../concepts/KI2C-02-STTS22H.md)
requires successful configuration, including BDU and `IF_ADD_INC`, before a
temperature read. A fresh [driver](../../devices/rlvgl-device-stts22h/src/lib.rs)
starts with `config: None`; `read_temperature` returns `NotConfigured` before
I/O. There is no public operation for importing an externally established
configuration. These requirements cannot both be fulfilled by a fresh
read-only application using the accepted API.

The owner can choose one of these concrete amendment directions. **None is
selected or adopted by this receipt.**

| Option | Required owner disposition and resulting acceptance |
| --- | --- |
| A: separately named configuration preparation | Amend KI2C-07 §6 to admit a bounded STTS22H configuration test before temperature capture. Define exact mode/averaging, expected CTRL values, prior-state handling, settling/readiness and restoration policy. Explicit operator authorization is required for those writes. KI2C-02's coherence contract remains intact. |
| B: strict read-only smoke with temperature held | Amend KI2C-07 §6 and acceptance to allow identity-only STTS22H smoke and explicitly classify temperature as `prerequisite-blocked` until an admitted preparation path exists. Identity success must not become full temperature conformance or phase completion. |
| C: observed-configuration adoption API | Amend KI2C-02 and KI2C-07 together to specify authoritative CTRL readback, validation of BDU/autoincrement/mode, and state adoption with failure behavior and negative fixtures. This is a new API/specification decision; no implementation is authorized from a proposed outline alone. |

Before executable diagnostic/log tooling, retain the owner-selected operation
contract and the adopted output schema as reviewable inputs. The proposed
`ki2c-conformance/v1 (proposed)` in
[wave1 preparation](v0.2.7-ki2c-software-preparation.md) is not an adopted version
or interoperable format. KI2C-00's Qwen executor/Llama judge discipline remains
applicable to a later implementation; host deterministic tests do not replace
that acceptance loop. No implementation or model-loop verdict is claimed here.

For hardware admission, supply every KI2C-07 §5 field before opening a bus:
identified board/revision/asset/operator; application and RLVGL identity;

controller identifiers; TEMP_ADDR high-impedance confirmation; measured PL
pull-up voltage and threshold assessment; PCM rails/RST/SCKI/BCK/LRCK evidence;
and permission for the exact typed operations. Preserve per-operation bus
errors and `pass`, `bus-error`, `semantic-failure`, `prerequisite-blocked` or
`not-admitted` classifications from KI2C-07 §3. PTN configuration magic is a
health result, not identity. PCM cannot be accessed before board-owned
