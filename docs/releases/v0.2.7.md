# rlvgl v0.2.7 release candidate

**October 10 execution:** the [restored candidate receipt](v0.2.7-execution-20261010.md)
records core 0.2.7, the six accepted decisions, fresh implementation evidence
and the two new stopped decision boundaries. The observations below retain
their historical dates and qualification.

**October 6 owner update:** [Current decisions](v0.2.7-owner-decisions.md)
record identity-only RLVGL smoke with existing reporting. Temperature validation
and prototype wiring gate only the CCPS dependencies that require them. The
historical observations below remain unchanged.

Repository release target: **v0.2.7**. Package versions are independent. Only
changed packages and necessary dependency requirements advance; unchanged
packages retain their published versions.

## Consolidated source

The candidate retains the published `7caee02e` v0.2.7 checkpoint and integrates:

- `58ef7166`: read-only Modbus request/response codec and a default-off offline
  P4 boot self-test, preserving headless application-service startup;
- `43c28ed9`: configurable IDF Rust target and C3 portable atomics; and
- Ratatui `3db4dd77`: portable atomic ownership for C3 widget shadows.

The earlier CCPS monitor and optional OLED/STTS22H adapter branches are already
contained in `7caee02e`. Older animation/input/audio branches remain historical
comparison material; this candidate does not import their entire histories.

## Qualification boundary

This release candidate carries the implemented native substrate and source
examples. It does not close WLD-02, the MPY binding/board/release initiative, or
the CPY binding/PyPI initiative. Their existing phase documents retain authority.
The C3 checkpoint establishes a Rust target check, not full IDF linking or
deployed hardware equivalence. The Modbus self-test performs no UART/GPIO access.

## Publication sequence

1. Validate the pinned Ratatui bridge package and publish its source checkpoint.
2. Validate the combined rlvgl source and changed package set; publish one
   integration branch retaining both handoff histories.
3. Update the selected parent branch to that exact rlvgl commit.
4. After required release gates and owner release review, create `v0.2.7` and
   publish the selected packages in dependency order.

The local integration checks and remaining release gates are recorded in
[the candidate validation receipt](v0.2.7-validation.md).

Unblocked family assignments and their SBC stopping points are recorded in
