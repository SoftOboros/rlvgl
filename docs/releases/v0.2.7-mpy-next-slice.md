## Narrow disposition required before implementation

The ratified documents require active metadata and deterministic single-revision
snapshots but do not settle the complete subscription-bearing in-process API.
The earlier sparse-style amendment explicitly excluded subscription rows. Prepare
an owning-family disposition covering:

1. **Revision consistency.** Decide whether successful subscription mutations
   become visible Stage mutations, or whether a coordinated cursor also freezes
   subscription revision and reports staleness. Specify failed/idempotent
   mutations, other-Stage mutations, teardown and Endpoint Epoch replacement.
   The two existing private revisions cannot silently be treated as one.
2. **Exact record and bounds.** Identify the reused `SubscriptionInfo` fields,
   actor/Stage association, deterministic row order, caller-visible budget,
   total count and truncation/redaction markers. Specify legacy zero-budget
   behavior and prohibit callable pointers. Existing integer `CallbackId` is
   not a Python callable; inclusion or omission must be explicit.
3. **Atomic page preparation.** Specify one allocation/reservation and cursor
   commit boundary across actor and subscription projection so failure retries
   the same page without publishing a partial record.

These are questions for the existing MPY-04/05 owners, not invented PCDN IDs.
This packet recommends preserving existing neutral metadata and cursor retry
guarantees; it does not select a new public contract or ratify a recommendation.
