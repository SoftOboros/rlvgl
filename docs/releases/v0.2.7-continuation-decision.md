# v0.2.7 continuation decision and implementation

October 6, 2026. The owner accepted decision 1: Gate P and publication must
use one frozen candidate, while any maintained publisher helper has a separate
recorded identity. The owner also directed removal of timed publishing runs.
[CRATES-CI-00 §15 0.1.2](../crates-ci/CRATES-CI-00-CONCEPTS.md) records this
**ratified semantic amendment before implementation**. It does not ratify the
independent staging correction in ERRATA-001.

## Local implementation

- `publish-continue.yml` now has only `workflow_dispatch`. It resolves latest
  and previous release tags to commit SHAs, including annotated tags.
- Its Gate P and publication jobs check out the same captured release commit.
  Publication depends on successful Gate P, retaining the three existing
  library, creator CLI and user-sim consumers.
- The publisher helper is preserved from the workflow revision and identified
  separately. Before authentication, exact HEAD and clean source must pass.
- The primary publisher's Gate P checkout explicitly pins `github.sha` too,
  and its publication job has the same exact-HEAD/clean-source guard.
- Existing release Environment/OIDC permissions remain. Nonpublishing recovery
  jobs explicitly grant only `contents: read`.
- Gate R retains its existing daily registry-truth verification and now follows
  successful primary or continuation publication. It performs verification,
  not timed publication.
- PR CI runs the new offline workflow-contract tests in a read-only job,
  using the existing declared PyYAML version. No local dependency was installed.

The publisher script has **no local five-crate cutoff**. It loops over the
complete changed set in dependency order, skips existing versions and stops
on failure. Existing indexing waits and HTTP 429/reset-time diagnostics remain.
Public upstream searches did not establish that server-side limits have been
removed; the policy change does not depend on that assumption. The
[upstream per-user/per-crate rate-limit issue](https://github.com/rust-lang/crates.io/issues/10396)
remains open in the inspected snapshot.

## Bounded verification

`python3 scripts/test_publish_workflows.py` passes four regression tests:

1. Workflow graph checks require the same source ref, successful Gate P before
   publication/authentication, all three consumers, manual-only recovery and
   retained verification/permissions.
2. The actual resolver bash runs in a local three-commit/two-annotated-tag
   fixture. Both publishers' actual guards reject later and dirty source and
   accept the selected clean tagged commit.
3. The real publisher script runs against fake Cargo and registry commands:
   nine selected packages are processed in order, and an existing version is
   skipped on retry. No upload command can reach real Cargo or crates.io.
4. A simulated HTTP 429 on the sixth package stops later dependents and retains
   the reset-time diagnostic for manual retry.

These are local fixture and workflow-graph checks. No GitHub workflow was
executed, token exchanged, package uploaded or registry limit tested by writes.
