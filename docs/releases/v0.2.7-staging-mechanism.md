# v0.2.7 staging mechanism decision packet

October 7, 2026. Proposed final mechanism disposition after decision 2.
The [wave-four trial](v0.2.7-packaging-wave4.md) resolves the retained core-lock
case without changing the source manifest or any archive member. This proposal
needs explicit owner ratification before governing-script implementation.

## Exact proposed boundary

Replace CRATES-CI-01b §5.2's blanket sibling-alias restriction with these rules:

1. Preserve the package's original manifest and Cargo-selected payload bytes.
   Cargo owns normalization, archive generation and temporary graph-lock updates.
   Original checkout locks remain unchanged; no manual archive or lock editing.
2. Permit a separately recorded **source graph-admission input** for genuine
   path-only dev dependencies that Cargo removes from the normalized archive,
   including their necessary real path dependency closure. Every admitted file
   comes from Cargo's source inventory at the same frozen candidate; missing
   files fail. No invented dependency manifests or placeholder implementations.
3. Route already-packaged dependencies to their extracted archives. A dev graph
   may refer back to the current source package to load an actual cycle; it does
   not supply a later package or consumer with live-source dependency resolution.
4. Keep source graph-admission paths out of the normalized package's resolution
   and verification graph. Audit the extracted metadata: the package itself and
   its staged predecessors may be local; other dependencies must be registry
   packages. Any source-admission path in that graph fails.
5. Retain every extracted predecessor, including core and the bridge, in the
   progressive patch table. No deferral or live-sibling fallback. A missing
   predecessor fails rather than searching the original checkout.
6. Retain the existing clean-source refusal, normal asset preparation, complete
   package inventory, metadata/version/content-drift guards, nested lock
   preservation and all three packaged-consumer gates.

The source graph-admission input is not a packaged-consumer source route. The
exception is limited to the pre-normalization graph needed by Cargo; archive
verification and final consumers remain extracted-only.

## Concrete evidence

The real core 0.2.7 trial uses the exact retained package lock and unchanged
original manifests. It admits the actual widgets/platform/audio/decomp/playit
dev graph and routes API only to a freshly extracted API 0.2.1 archive. Cargo
produces all 84 expected members with no byte differences against the retained
actual package, including Cargo.lock and .cargo_vcs_info.json. Cargo changes
only the external input graph lock; the packaged lock remains exact.

Resolved extracted-core metadata has 26 packages. Its only local manifests are
the extracted core and extracted API; all others are registry packages. It
contains no source-admission path and leaves the archive payload unchanged.
The wave-four receipt records the missing-predecessor control and preservation.

These are one-package diagnostics. They do not establish full 31-package staging,
asset preparation, clean CI, published-content drift or consumer success.
