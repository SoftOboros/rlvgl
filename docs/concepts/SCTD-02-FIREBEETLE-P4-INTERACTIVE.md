# SCTD-02 - FireBeetle 2 ESP32-P4 Interactive Mount

**Status:** DRAFT 2026-06-20. Awaiting ratification. Normative for the
SCTD initiative's FireBeetle-2-ESP32-P4 ESP-IDF target and the
interactive Dining Philosophers extension. Builds on
[`SCTD-00-CONCEPTS.md`](SCTD-00-CONCEPTS.md) (ratified 2026-06-19) and the
SCTD-01 implementation (landed 2026-06-20, `c2f7d39`).

Requesting ticket: realize the SCXML state-chart demo on the FireBeetle 2
platform (already running rlvgl over ESP-IDF on the DFR0550-V2 5″ 800×480
DSI panel). Separate / pipeline the machine-tick ↔ framebuffer
relationship so the double buffer flips only after a frame is fully
composed, paced for human reaction time rather than frame accuracy.
Introduce external-input "wrinkles" that gate the Dining Philosophers
machine — arrive / depart philosophers, a panic deadlock-break, and a
simulation reset — through on-screen touch controls, with pause/resume
and speed as host-side simulation controls.

## 1. Purpose

Prove the SCTD tutorial demo runs as an **interactive** application on
real embedded hardware — the FireBeetle 2 ESP32-P4 driving the DFR0550-V2
5″ 800×480 DSI panel through ESP-IDF — and that an external-input-gated
state machine generated by the iState/scjson path behaves correctly under
human-paced touch interaction on that panel. SCTD-01 proved the demo
builds and its machines run on host/sim/bare-metal/UEFI; SCTD-02 proves it
*runs and responds to a person* on the panel that is already shipping.

## 2. Problem Statement

The shipped FireBeetle-2-P4 path already mounts an rlvgl widget tree:

- `examples/beetle-esp32p4-idf/` is an ESP-IDF app where C owns the
  hardware and a `no_std` Rust staticlib (`librlvgl_app.a`,
  `riscv32imafc-unknown-none-elf`, ilp32f) owns the pixels via
  `rlvgl_app_render(fb, w, h, touch_x, touch_y, touch_active)`
  (`components/rlvgl_app/rust/src/lib.rs:299`).
- The C host (`main/dfr0550_idf_compare.c:352-389`) double-buffers
  (`num_fbs=2`), renders the Rust payload into the off-screen buffer,
  flips it tear-free with `esp_lcd_panel_draw_bitmap` on vblank, and
  re-fills continuously at ~30 Hz (the DFR0550-V2 bridge desyncs to white
  if the framebuffer goes idle).
- Touch is wired: the C host samples the FT5x06 at I2C 0x38, axis-flips
  into screen space, and passes the live point each frame
  (`dfr0550_idf_compare.c:365-384`); the Rust payload debounces it into a
  single `PressRelease` per physical tap
  (`rust/src/lib.rs:330-343`).

Three gaps stand between that and the requested deliverable:

1. **Payload is disco-demo, not SCTD.** The IDF glue mounts
   `rlvgl-app-disco-demo` (`rust/src/lib.rs:30`), not the SCTD controller.
2. **Dining Philosophers is a closed timer-driven system.** The SCTD-01
   faithful machine has no external lifecycle inputs — philosophers cannot
   be admitted or removed, deadlock cannot be forced or broken, and the
   simulation cannot be reset (the machine accepts only `taken.*` and
   `update.delay` externally). There is nothing for a person to *do*.
3. **The machine would advance at refill rate.** Disco-demo ticks once per
   ~30 Hz frame; a Dining Philosophers machine stepped 30×/s is
   unwatchable. The machine logical-time advance is not decoupled from the
   framebuffer refill cadence.

SCTD-02 exists to freeze, before code lands: which machine the interactive
variant is and how its inputs are admitted; how the on-screen controls
dispatch into it; how the FireBeetle-2-P4 ESP-IDF target wrapper mounts
the SCTD payload without disturbing the hardware authority; and the
compose-then-flip + decoupled-tick cadence contract.

## 5. Frozen Decisions - Interactive Machine Admission

1. **New admitted machine.** SCTD-02 MUST admit an **Interactive Dining
   Philosophers** machine as a distinct Tutorial Machine. It is a
   normalized variant with documented provenance to the SCTD-01 faithful
   DP per SCTD-00 §5 item 3. The faithful DP machine and its vector tests
   MUST remain unchanged. Both machines MAY be selectable; the interactive
   variant is the FireBeetle demo's primary machine.

2. **Lifecycle event set (frozen enum).** The Interactive DP machine
   admits exactly these host-injected external events:
   `PHILOSOPHER_ARRIVE`, `PHILOSOPHER_DEPART`, `DEADLOCK_BREAK`,
   `SIMULATION_RESET`. **Registration policy: Specification Required** —
   adding a value requires an SCTD-02 §15 walkthrough update, no SCTD-00
   amendment (this enum is local to the SCTD-02 contract surface). The
   existing `taken.*` / `update.delay` external events are retained.

3. **Seating model.** The machine MUST model each of the 5 philosopher
   seats with an inactive ("lobby"/empty) and an active lifecycle, so
   `PHILOSOPHER_ARRIVE` admits the next empty seat into the
   thinking/hungry/eating cycle and `PHILOSOPHER_DEPART` returns a seated
   philosopher to empty. The classical 5-fork topology is preserved; an
   empty seat holds no forks. (See PCDN-02-02 for the arrival-order
   default.)

4. **Depart-while-eating safety.** `PHILOSOPHER_DEPART` received while the
   target is not `Thinking` MUST set a **pending depart** datamodel
   boolean rather than transitioning immediately; the philosopher
   completes its atomic eat→release→think cycle, and a **state-scoped**
   `<transition>` inside the `Thinking` state honours the pending depart.
   This preserves the fork-release invariant and uses no `In()` predicate
   (the state-scoped form is the admitted replacement — scjson ERRATA-003).

5. **Event payload shape.** Where a lifecycle event needs to name a seat,
   the seat id MUST be carried as the scalar `_event.data` value
   (an integer), not as a nested `_event.data.id` field. Two-level member
   access is outside the reliably-admitted evaluation path; the scalar
   form is admitted and tested (M1P6 D-M1P6-2 / `_event.data` evaluation).

6. **Deadlock-break semantics.** `DEADLOCK_BREAK` MUST force-release fork
   state so a stalled configuration can recover, expressed as admitted
   `<assign>`/`<foreach>` datamodel actions on the existing fork-tracking
   variables — not as a host reach-in past the generated public API
   (SCTD-00 §6.9).

7. **Reset semantics.** `SIMULATION_RESET` is satisfied by the host
   **re-instantiating** the generated machine (`Machine::new()` +
   `start()`) behind the machine adapter; SCTD-02 MUST NOT require a
   generated in-place `reset()` method. The `SIMULATION_RESET` event MAY
   additionally exist as an admitted no-op/terminal handle for trace
   symmetry, but the authoritative reset is host re-instantiation.

8. **Verification vectors required.** The Interactive DP machine MUST
   carry deterministic vector tests covering: an arrive→think→hungry→eat
   cycle, a depart-while-thinking, a depart-while-eating that defers via
   pending-depart, a deadlock-break recovery, and (host-side) a reset to
   initial configuration. Required before it appears in the selector
   (SCTD-00 §5 item 5 / §9).

## 6. Frozen Decisions - Interactive App Surface

1. **Controls live in the app crate.** The on-screen control surface and
   the host simulation controls MUST live in `rlvgl-app-sctd-demo`
   (target-neutral). No board-specific code, PAC access, or wall-clock
   assumption enters the app crate (SCTD-00 §6.1). The FireBeetle target
   wrapper supplies only the framebuffer, the touch point, and the tick.

2. **On-screen touch targets.** The Interactive DP machine panel MUST
   present touch targets for the lifecycle events — Arrive, Depart, Panic
   (`DEADLOCK_BREAK`), Reset — plus the host controls Pause/Resume and
   Speed. Inputs are physical touch: the existing FT5x06→`PressRelease`
   path (no physical GPIO buttons). The 800×480 panel is the design size.

3. **Event dispatch through the adapter.** Lifecycle-event controls MUST
   dispatch named SCXML events through the machine adapter's public
   `step(name, data)` surface (SCTD-00 §6.9). UI code MUST NOT reach into
   generated internals beyond the public API and self-manifest vocabulary.

4. **Host controls gate the tick, not the machine.** Pause/Resume MUST
   suspend the logical tick (the machine receives no events and does not
   advance) without mutating machine state; resume continues from the
   suspended configuration. Speed MUST scale the logical-ms advanced per
   refill (§7). Neither injects an SCXML event — suspending or scaling the
   simulation clock is a harness meta-operation, not a state transition.

5. **State observability preserved.** Per SCTD-00 §6.8 the panel MUST keep
   showing current active state names (per-seat phase + fork ownership)
   alongside the controls; machine-specific visualization stays secondary
   to observability.

6. **Disco-demo IDF mount preserved.** Mounting SCTD on the FireBeetle-2-P4
   IDF host MUST NOT regress the existing disco-demo IDF payload. The
   payload selection mechanism is settled in PCDN-02-01 (default
   recommendation: a build-time selector keeping disco-demo as an
   alternative, so neither payload is deleted).

7. **Selector unchanged.** The right-edge selector position and semantics
   (SCTD-00 §6.2) are unchanged; the interactive machine is an additional
   selectable entry alongside the SCTD-01 entries.

## 7. Frozen Decisions - Target Portability & Cadence

1. **New supported target.** SCTD-02 adds **FireBeetle 2 ESP32-P4 +
   DFR0550-V2, via `examples/beetle-esp32p4-idf` (ESP-IDF)** to the SCTD
   supported-target set. This amends SCTD-00 §7.2 (recorded in SCTD-00
   §15 first). The mount is the ESP-IDF hybrid only; the raw-PAC
   `examples/beetle-esp32p4` path is out of scope (§11).

2. **Hardware-authority boundary.** SCTD-02 MUST NOT modify the C host's
   DSI/DPI/PSRAM/LDO/I2C-bridge/cache/touch-read/double-buffer/flip
   sequence (`dfr0550_idf_compare.c`). The only SCTD-02 changes to the IDF
   app are: the Rust payload behind `rlvgl_app_render`, payload selection
   (PCDN-02-01), and (if needed) an additive C-ABI surface that preserves
   the existing `rlvgl_app_render` signature.

3. **Compose-then-flip (INV-SCTD02-1).** The panel flip
   (`esp_lcd_panel_draw_bitmap`) MUST occur only after the Rust payload
   has fully composed the frame into the off-screen buffer and the C2M
   cache writeback has run. The shipped C host already satisfies this
   (`dfr0550_idf_compare.c:384-387`); SCTD-02 pins it as an invariant —
   no partial-compose frame may be presented, and the payload MUST fully
   paint every frame it is handed (the buffers ping-pong, so each frame
   is composed from a cleared buffer, not differentially).

4. **Decoupled logical-tick cadence (INV-SCTD02-2).** The Interactive DP
   machine's logical-time advance MUST be decoupled from the ~30 Hz
   refill. The payload MUST step the machine on a logical clock paced so a
   philosopher's think and eat phases are each human-watchable (target:
   on the order of ~1-3 s of wall time per phase at default speed), while
   the C host continues to refill and flip at ~30 Hz (re-composing the
   current configuration each refill, as the bridge requires). Pause halts
   the logical advance; speed scales logical-ms per refill. The default
   pacing and speed steps are settled in PCDN-02-03.

5. **Resource posture unchanged.** The payload MUST remain `no_std +
   alloc` over the IDF/newlib heap (`rust/src/lib.rs:57-74`), within the
   resource budget SCTD-00 §7.4 already requires; the interactive machine
   MUST lower into that budget (admitted subset, no heap-pathological
   datamodel — §8).

6. **Build gate.** `idf.py set-target esp32p4 build` (after
   `. ~/esp/esp-idf/export.sh`) MUST build the SCTD Rust staticlib + the
   C host. The Rust payload's dependency on `rlvgl-app-sctd-demo` MUST NOT
   break the SCTD-01 host/sim/`thumbv7em`/UEFI build gates, which remain
   green (the app crate stays target-neutral).

7. **On-board flash + verify gate.** SCTD-02 implementation is complete
   only when the firmware is flashed to a physical FireBeetle 2 and the
   interactive Dining Philosophers demo is confirmed running on the real
   DFR0550-V2 panel: state transitions visible at human pace, and each
   on-screen control (arrive / depart / panic / reset / pause / speed)
   observably affecting the machine. This is a bench round requiring the
   operator's board + an explicit flash authorization; the assistant does
   not flash unprompted.

## 8. Frozen Decisions - iState MCP Boundary

1. **Same generation authority.** The Interactive DP machine MUST be
   generated through the iState M1P6 path (SCTD-00 §8), not hand-written.
   No new generator capability is required: per the SCTD-02 feasibility
   review, every lifecycle wrinkle lowers within the admitted-ECMAScript
   subset — bare named external events, a boolean `<assign>` + `cond`
   guard (pending depart), scalar `_event.data`, state-scoped transitions
   (in lieu of `In()`), and `<assign>`/`<foreach>` fork-state mutation for
   deadlock-break.

2. **No `In()` dependency.** The machine MUST NOT require the unadmitted
   `In(<stateid>)` predicate (scjson ERRATA-003). "Valid only in
   `Thinking`" is expressed structurally as a state-scoped transition.

3. **Self-manifest + no runtime SCXML.** Unchanged from SCTD-00 §8: the
   machine carries a self-manifest; the target binary MUST NOT parse SCXML
   at runtime.

## 9. Frozen Decisions - Testing

1. **Machine vectors.** Per §5.8, runnable with
   `cargo test --manifest-path <machine>/Cargo.toml`.
2. **App-level tests.** The Tutorial Demo App MUST gain unit tests for the
   new control surface: each lifecycle control dispatches the correct
   named event; pause suspends the tick without mutating state; speed
   scales the logical advance; reset re-instantiates the machine.
3. **Simulator smoke.** The host/disco simulator MUST be able to select
   the interactive machine and exercise arrive / depart (both timings) /
   panic / reset, proving the full interaction loop without hardware.
4. **On-board smoke.** Per §7.7, the bench round confirms the same loop on
   the physical panel.
5. **Build-gate regression.** The SCTD-01 build gates (host/sim/
   `thumbv7em`/UEFI) MUST stay green; the FireBeetle IDF build is an
   additional gate, not a replacement.

## 11. Non-Goals

- No raw-PAC mount. SCTD-02 rides the ESP-IDF hybrid only; the raw-PAC
  `examples/beetle-esp32p4` port (DPHY-lock-blocked, ERRATA-009) is out of
  scope.
- No new DSI/DPI/PSRAM/touch bring-up. The BEETLE family + C host own it.
- No real Skoda Bolero. The media-player normalized variant (SCTD-01)
  remains `In()`-blocked; admitting `In()` is future scjson work.
- No FreeRTOS-on-STM32H747I-DISCO mount. That remains the separate
  deferred SCTD exception (SCTD-00 §15, 2026-06-20); it is unrelated to
  the FreeRTOS that ESP-IDF provides natively here.
- No physical GPIO buttons. Interaction is on-screen touch.
- No change to disco-demo selector semantics or the SCTD-01 machines.
