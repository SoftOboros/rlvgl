# KI2C-04 — PTN3460 Driver As-Built Handoff

**Status:** Complete 2026-07-15. Accepted by deterministic gates and the local
Llama tactical judge. KI2C-05 is unblocked.

## 0. Authority Policy

This phase implements only the bounded PTN3460 control-plane surface admitted
by KI2C-00. Device behavior is sourced from NXP PTN3460 product data sheet
Rev. 4 (12-Mar-2014) and AN11128 Programming Guide Rev. 1.9 (01-Jun-2016).
Memory Alpha notebook 57 document 1263 remains the project evidence handle;
its MCP endpoint returned HTTP 502 throughout this pass, so the primary NXP
sources were expanded directly. Backfill completed during KI2C-06 compression.

## 1. Purpose

Provide a publishable, allocation-free `no_std` PTN3460 crate compatible with
RLVGL's `embedded-hal` 1.0 I2C boundary. Correct the address representation,
expose a truthful health read, and admit the smallest self-contained typed
electrical configuration without exposing destructive flash or panel behavior.

## 2. Outcome

`devices/rlvgl-device-ptn3460` is a workspace crate at version `0.2.5`. It
owns an arbitrary `I2c<SevenBitAddress>` handle, defaults to the board's
DEV_CFG-low strap, preserves backend errors, and returns the handle through
`release`.

KI2C-04 also corrected `rlvgl-kria-i2c::PTN3460` from `0x40` to the normalized
seven-bit address `0x20` and refreshed all affected support tests and hashes.

## 3. Glossary

| Term | Meaning |
|---|---|
| Address byte | Eight-bit on-wire slave address plus R/W bit; NXP writes `0x40` or `0xc0`. |
| Seven-bit address | Address representation required by `embedded-hal`; `0x20` or `0x60`. |
| Configuration magic | Big-endian word at `0xec`; `0x12345678` means the flashed configuration table is valid. |
| Center spread | Programmable LVDS clock-frequency spreading depth in register `0x82`. |
| Output swing | Programmable LVDS differential amplitude in register `0x82`. |

## 5. Address Reconciliation

NXP calls DEV_CFG-low `0x40` and DEV_CFG-open `0xc0`, and its programming
examples send those values as the first on-wire byte. `0xc0` cannot be a
seven-bit address. Removing the R/W bit yields `0x20` and `0x60`, respectively.
The crate's `Address` values and Kria endpoint therefore use those normalized
values.

## 6. Implemented Register Contract

| Register | Size | Driver behavior |
|---|---:|---|
| LVDS electrical | `0x82`, 1 byte | Typed read/write with every reserved encoding rejected. |
| Configuration magic | `0xec`, 4 bytes | Big-endian read returned by `probe`. |

The product data sheet and guide admit no fixed silicon-identity register.
`probe` therefore reports the completed configuration-magic read without
claiming identity. Invalid magic is data (`configuration_valid() == false`),
not a fabricated bus or device error.

## 7. Implemented Configuration Contract

`LvdsElectricalConfig` admits center spread disabled, 0.5, 1.0, 1.5, 2.0,
or 2.5 percent and differential swing 150 through 450 mV in 50 mV steps.
Its default is the documented `0x03`: spread disabled and 300 mV swing.

The decoder rejects upper reserved bits, spread codes 6/7, and swing code 7
while preserving the entire offending byte. The writer emits exactly
`[0x82, value]`; it cannot touch EDID, pin precedence, panel timing, or flash.

## 9. Model-Loop Record

The local `qwen2.5-coder:7b` executor was limited to `src/lib.rs`. Its initial
candidate fabricated an always-valid zero-sized probe, attempted to construct
an associated bus error value, used the wrong decode error generic, and omitted
reserved-bit checks. The first revision switched to the removed
`embedded_hal::blocking` module and discarded most required APIs. The final
revision used wrong transactions, byte order, method names, and return types
and was syntactically invalid. The fixed tests were never relaxed.

The primary executor escalation replaced only `src/lib.rs`. All §8 gates then
passed. The local `llama3.1:8b` judge returned `ACCEPT`; a retry corrected only
its fenced/misclassified JSON envelope and made no code change.

## 10. Reconciliation

The original notebook and KI2C-00 inventory repeated NXP's `0x40` label as if
it were already seven-bit. AN11128's on-wire protocol examples and the paired
`0xc0` value prove otherwise. KI2C-00, KI2C-01, the Kria endpoint, tests, and
hashes are amended together.

The requested “identity/health” surface was narrowed to health. Neither
authoritative source provides a silicon identity register, so accepting a
specific identity value would invent evidence.

## 11. Non-Goals

- Silicon identity claims unsupported by a register.
- EDID emulation selection or EDID contents.
- Flash erase/program/trigger commands and their required delays.
- Pin overrides, link packing, lane setup, panel timing, PWM, or backlight.
- Reset, PD_N, or HPDRX GPIO ownership.
- Async I2C or Linux-specific behavior.
