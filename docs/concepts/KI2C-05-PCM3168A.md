# KI2C-05 — PCM3168A Driver As-Built Handoff

**Status:** Complete 2026-07-15. Accepted by deterministic gates and the local
Llama tactical judge. KI2C-06 is unblocked.

## 0. Authority Policy

This phase implements only the PCM3168A control-plane surface admitted by
KI2C-00. Device behavior is sourced from Texas Instruments SBAS452A Rev. A
(September 2008, revised January 2016). Memory Alpha notebook 57 document 1262
remains the project evidence handle; its MCP endpoint returned HTTP 502
throughout this pass, so the official TI source was expanded directly and
artifact backfill was deferred until the KI2C-06 compression pass.

## 1. Purpose

Provide a publishable, allocation-free `no_std` PCM3168A crate compatible with
RLVGL's `embedded-hal` 1.0 I2C boundary. Make hardware readiness explicit in
the type system, expose a truthful control-plane health read, and admit only
the smallest common slave-format and resynchronization operations.

## 2. Outcome

`devices/rlvgl-device-pcm3168a` is a workspace crate at version `0.2.5`. It
owns an arbitrary `I2c<SevenBitAddress>` handle, defaults to the Kria `0x44`
strap, preserves backend errors, and returns the handle through `release`.

An `Unverified` driver has no I2C methods. It transitions to `Ready` only with
a `HardwareReady` token that explicitly attests stable rails, released RST,
and synchronized/ratiometric SCKI, BCK, and LRCK.

## 3. Glossary

| Term | Meaning |
|---|---|
| SCKI | External codec system clock. |
| BCK/LRCK | Bit clock and sample/frame clock for the ADC/DAC serial interfaces. |
| MRST | Mode-control-register reset bit in register `0x40`. |
| SRST | ADC/DAC system resynchronization bit in register `0x40`. |
| Ready typestate | Driver state in which the board layer has attested external prerequisites. |

## 5. Readiness Contract

`HardwareReady::new` rejects unstable rails, asserted reset, or unsynchronized
clocks in that order. `into_ready` consumes the token without a bus operation.
Only `Pcm3168a<I2C, Ready>` implements probe/configuration/resynchronization.

The token is an explicit board-layer attestation, not a sensor measurement.
The integration layer remains responsible for GPIO direction/level, clock
generation, the 3846-SCKI reset-release interval, audio muting, and settling.

## 6. Implemented Register Contract

| Register | Driver behavior |
|---|---|
| `0x40` reset control | Typed health read; rejects nonzero reserved bits 5:2. |
| `0x41` DAC control 1 | Writes a common audio format with slave and default power-save-mode fields. |
| `0x51` ADC control 1 | Writes the same common audio format with slave fields. |

The PCM3168A has no admitted silicon-identity register. `probe` therefore
returns MRST, SRST, and sampling mode only and does not claim identity.

## 7. Typed Configuration and Resynchronization

`AudioFormat` admits the eight codes common to both DAC and ADC in slave mode:
24-bit I2S, 24-bit left/right justified, 16-bit right justified, DSP I2S/left,
and TDM I2S/left. DAC-only high-speed TDM and every master-clock mode remain
excluded.

`resynchronize` first reads and validates `0x40`, then writes MRST normal,
SRST low, reserved bits zero, and the preserved sampling mode. TI documents
that SRST auto-restores and that pop noise may occur; callers own muting and
post-resynchronization settling.

## 10. Reconciliation

The “probe” requested by the initiative cannot be an identity probe because
SBAS452A defines no silicon ID register. It is named and documented as a
reset-state control-plane health read.

The datasheet states no mandatory order between VCC and VDD but recommends
simultaneous power-on to avoid unexpected output behavior. The crate does not
translate that into GPIO or rail sequencing; its readiness token requires the
board layer to resolve and attest the actual hardware state.

## 11. Non-Goals

- Audio sample transport.
- GPIO ownership for RST, clocks, mute, overflow, or zero flags.
- Clock generation or validation from measured frequencies.
- DAC-only high-speed TDM or any ADC/DAC master mode.
- Attenuation, mute, input topology, phase, filters, or power-save controls.
- Automatic delay, fade, or pop suppression.
- Raw or arbitrary register access.
